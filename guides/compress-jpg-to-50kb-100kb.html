Size target guide

Compress JPG to 50KB or 100KB: which target wins

Between 20KB and 100KB there is a wide band where a photo stops looking damaged and starts looking merely small. Choosing inside that band is a matter of what the image must communicate, not a single “best” number.

Updated 14 November 20267 min readTool runs locally

Quick answer

Use 50KB when the portal caps the file and the image is a simple portrait, thumbnail or product shot. Use 100KB when the image contains text, faces at medium size, or product detail that a reviewer must judge. If the portal allows 100KB, the extra 50KB usually buys visibly cleaner edges than spending it on a larger pixel canvas.

The gap between 50KB and 100KB is not linear

Doubling the byte budget does not double perceived quality. JPEG quality is a curve: the first reductions remove information the eye barely notices, while later reductions start erasing texture and edges. Moving from a very aggressive 20KB target to 50KB often produces the largest visible improvement. Moving from 50KB to 100KB is quieter, but it is the difference between a face that looks slightly waxy and one that keeps pores, hair strands and the edge between lips and skin.

The pixel count matters as much as the bytes. At 600×450, 50KB provides about 1.52 bits per pixel and 100KB provides about 3.03. At 1200×900, the same byte counts fall to 0.38 and 0.76 bits per pixel, which is not enough for a detailed photograph. This is why a preset that works for a small headshot can fail badly on a full-size landscape shot.

When 50KB is the right call

A 50KB cap is common on application forms, school portals and older content systems. It is also a sensible self-imposed budget for a website thumbnail or a directory listing. At 50KB, a 600×450 portrait usually keeps a clean face, a recognisable background and enough contrast for a reviewer to identify the subject. The file downloads quickly on a weak connection and sits comfortably inside most email clients.

The failure mode at 50KB is texture. Knitted clothing, foliage, gravel and fine hair lose definition first. If the image’s purpose is to show a product’s material or a document’s text, 50KB is usually the wrong budget. If the purpose is identity or a quick visual impression, it is often enough.

When 100KB earns its place

A 100KB file is still small by camera standards, but it gives the encoder room to preserve edges. That matters for three categories: faces that will be reviewed closely, images that contain small text, and product photos where colour and surface matter. A 100KB image at 800×600 is also a reasonable default for a blog hero or an Open Graph preview, where the file is fetched once and cached.

Do not assume 100KB is always safer. Some portals specify a range, such as 20KB to 50KB, and reject anything above the ceiling. Others count all uploaded files together, so five 100KB images exceed a 400KB total. Read the constraint as a set of numbers, not a single familiar label.

Try both targets on the same file

Compress once at 50KB, then once at 100KB, and compare at 100% zoom. Look at the eyes, the boundary between hair and background, and any text. The difference should be visible at 100KB; if it is not, keep the smaller file. On a slow connection, the 50KB version is the better user experience.

What the preset dimensions mean

The homepage presets use a starting canvas rather than a guarantee. For 50KB, the starting fit is 1200×900; for 100KB, it is 1600×1200. Those numbers come from the assumption that a web image rarely needs more than that for its display size. They are not requirements. If your source is a 600×600 headshot, the tool will not upscale it; it keeps the original dimensions and spends the byte budget on quality.

This distinction is important when a portal demands a minimum dimension. A 1600×1200 starting fit for 100KB can produce a soft image because 100KB is only 0.43 bits per pixel at that size. For a 600×600 portrait, the same 100KB is 2.28 bits per pixel and looks much better. The correct move is to set the intended display dimensions first, then choose the target.

A decision checklist

  1. Does the image contain text? If yes, prefer 100KB or larger, and check letter edges at 100%.
  2. Will a human judge the face? Use at least 50KB for a 600×450 portrait, 100KB if the face fills the frame.
  3. Is it a website thumbnail? 30KB to 50KB is usually plenty at 300–600 pixels wide.
  4. Is it a hero image? Use 100KB to 200KB and modern delivery, not a 20KB compromise.
  5. Does the form state a maximum? Stay 5–10% below it to absorb byte-count differences.
  6. Does the form state a minimum? Do not go under it, even if the image would look better smaller.

Quality modes and how they change the result

The homepage offers three priorities. Balanced quality is the default and searches a wide quality range. Keep more detail narrows the search toward higher quality and accepts larger dimensions only when the target allows it. Prefer smaller output pushes the search toward the low end. The guide tool uses a balanced search by default because its job is to demonstrate the target math, not to expose every control.

If you are preparing a file for an uncertain portal, balanced is the safest choice. If the portal has a hard ceiling and no minimum dimensions, prefer smaller output and verify the face still reads. If the image will be printed or reviewed closely, use keep more detail and accept a larger byte count if the form permits.

Frequently asked questions

Can I hit exactly 100KB?

Not exactly, and you should not want to. The encoder produces a file at or below the target, typically a few percent under. A file that reports 98.7KB is a success; forcing exactly 102,400 bytes would require padding that adds no value.

Why does a 100KB preset sometimes return 60KB?

Because the image reached the target before the tool needed the full budget. Hitting the ceiling is not the goal; producing the smallest clean file that still looks right is. If you need the extra detail, choose a higher target or a larger starting dimension.

Should I use 50KB for email attachments?

It is usually more than enough for a single photo. Email clients care about total message size, and base64 encoding adds roughly a third. A 50KB photo becomes about 67KB on the wire, which is trivial next to a 25MB mailbox limit.
