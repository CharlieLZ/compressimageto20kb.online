Compress JPG to 20KB: what actually fits

Twenty kilobytes is not a quality setting. It is a hard budget, and every pixel in the image has to share it. This guide shows the arithmetic, the visual cost, and a working compressor so you can test the result before a portal rejects it.

Updated 14 November 20268 min readTool runs locally

Quick answer

To compress a JPG to 20KB, reduce its pixel dimensions first, then lower JPEG quality. A 20KB file is 20,480 bytes in most tools, which is only about 0.61 bits per pixel at 600×450. For photos with faces or fine texture, a 400×300 to 500×375 result usually looks cleaner than forcing 600×450 down to the same byte count.

What “20KB” means in bytes

File size is counted in bytes, but interfaces label it in kilobytes. The convention most compression tools use is binary: 1KB equals 1,024 bytes, so 20KB equals 20,480 bytes. Some upload portals instead mean 20,000 bytes, which is 480 bytes smaller. That gap sounds trivial until a form rejects a file at 20.1KB. When the limit is rigid, target 19.5KB or less and read the exact byte count your tool reports, not just the rounded label.

The distinction matters because JPEG encoders do not hit an exact size. They compress a block of pixels and produce whatever byte count those blocks require. A tool can search for a combination of dimensions and quality that lands under the limit, but it cannot promise an exact 20,480-byte file without padding, and padding a JPEG with junk bytes is not a real optimisation.

The bit budget behind a 20KB target

A JPEG stores three colour channels, usually with chroma subsampling, and spends most of its bytes on luminance detail. A rough way to see how aggressive a target is: multiply the byte count by eight to get bits, then divide by the pixel count. The result is the average number of bits available per pixel before compression overhead.

These numbers explain why the same 20KB target looks fine on one photo and terrible on another. A studio portrait against a plain wall has large areas that compress cheaply. A tree canopy, a brick wall or a page of text has high-frequency detail in every block, so the encoder runs out of bits quickly and either blurs or produces blocking artefacts.

Dimensions or quality: which to cut first

When a JPG is far above the target, you have two levers. Lowering quality keeps the pixel count and throws away precision inside each 8×8 block. Reducing dimensions removes pixels entirely, then encodes the smaller image at a healthier quality. For a strict 20KB limit, reducing dimensions first usually produces the better-looking result, because the viewer sees fewer pixels but each one is represented more accurately.

There is a limit to that logic. If the form requires a minimum dimension, such as 600×600 for a profile photo, you cannot shrink below it. In that case the file must accept a lower quality, and the honest outcome may be “closest match” rather than an exact 20KB file. A compressor that silently destroys the image to hit the number is not helping you pass a human review.

Useful rule: choose the smallest dimensions that still satisfy the form, then spend the remaining byte budget on quality. Do not choose the largest allowed dimensions and force the quality down until the file fits.

A repeatable 20KB workflow

  1. Read the form twice. Write down the maximum size, the minimum and maximum dimensions, the required aspect ratio and the accepted formats. If the form says “20KB, 600×600 minimum”, those two constraints may conflict.
  2. Crop before compressing. Remove empty background, borders and anything the form does not need. A tighter crop gives the subject more pixels inside the same byte budget.
  3. Set the target to 20KB. Let the tool choose dimensions and quality together. Do not manually save at quality 10 in an image editor and hope the result lands under the limit.
  4. Check the exact bytes. Open the downloaded file’s properties. If the portal counts 20KB as 20,000 bytes, leave a margin.
  5. Look at the face or the label. Zoom to 100%. If eyes, text or product edges are mushy, reduce dimensions and re-encode rather than lowering quality further.
  6. Keep the original. The compressed copy is for the upload. Keep the full-resolution file for print, future applications and any appeal process.

Why some images cannot reach 20KB cleanly

JPEG divides the image into 8×8 blocks and quantises the frequency information in each block. When the target is extremely small, the quantisation table becomes coarse. Flat areas survive because neighbouring blocks are similar. Detailed areas do not: edges spread, colour bleeds and the image develops a blocky texture. At the extreme, the encoder can still produce a 20KB file, but the result may be a blurry approximation that no longer serves its purpose.

A responsible compressor therefore has a stopping condition. PixelPress uses a minimum quality floor and reports “Closest match” when the cleanest result remains above the target. That label is not a failure of the tool; it is information that the source image and the target are in conflict. The fix is usually a tighter crop, smaller dimensions, or a form that accepts 50KB.

Privacy and metadata

When a JPEG is decoded into a canvas and re-encoded, the new file contains pixel data and a fresh JFIF header, not the original EXIF block. Device model, capture time, GPS coordinates and editing history are not carried over. That is a useful side effect for personal photos submitted to public portals. It is not a guarantee of anonymity: the image content itself can still identify a person or location, and some portals keep the uploaded file. The original file on your device is never modified by the browser tool.

Common rejection reasons and what to change

  • “File too large” after the tool said 20KB. The portal may count 20,000 bytes, or it may include form overhead. Aim for 19KB.
  • “Dimensions too small.” You reduced pixels to hit the byte limit. Crop instead, or accept a slightly larger file if the form allows it.
  • “Invalid file type.” Renaming a PNG to .jpg does not change its encoding. Re-encode through a JPEG tool.
  • “Photo is blurry.” The target forced excessive quantisation. Use a tighter crop and a smaller canvas rather than a lower quality slider.
  • “Head not centred” or “background not plain.” This is a composition rule, not a compression problem. Fix the crop before compressing again.

Frequently asked questions

Is 20KB enough for a passport or ID photo?

Usually not on its own. Many identity portals specify both a pixel size, such as 600×600, and a byte range. A 600×600 photo at 20KB is about 0.46 bits per pixel, which is extremely tight for a face. Follow the portal’s stated range; if it allows 50KB or 100KB, use the extra room.

Should I convert PNG screenshots to JPG for a 20KB limit?

Only if the screenshot has photographic content or gradients. Flat interface screenshots and text compress better as PNG, and JPEG adds ringing around letters. If the portal demands JPG, a screenshot with large flat areas can still fit 20KB, but check the text at 100% zoom.

Does lowering quality twice make the file smaller?

Not reliably. Re-encoding an already compressed JPEG adds another generation of loss and may even increase size because the encoder has to represent existing artefacts. Always compress from the best original you have, once, to the final target.
