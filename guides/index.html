Start with the restriction, not the file

A rejection message usually names one constraint: a maximum file size, a minimum or maximum pixel dimension, a required aspect ratio, or a format. Those four constraints are not interchangeable. A 4000×3000 photo can be squeezed under 20KB and still be rejected because the portal wanted 600×600 pixels. A 600×600 photo can fit the dimensions and still fail because the encoded file is 48KB. Reading the form first saves an upload cycle.

The guides below are ordered by how often that confusion appears. The first three cover strict kilobyte targets and portal limits. The middle four cover documents where dimensions matter more than bytes: passport photos, job applications, email attachments and print output. The final three cover quality, format choice and batch work for websites.

What every guide has in common

Compression is arithmetic plus a visual judgement. The arithmetic is knowable: eight bits per byte, a fixed target in kilobytes, and a pixel count that determines how many bits each pixel can receive. The visual judgement is yours, but it becomes much easier once the arithmetic is visible. A target that forces 0.6 bits per pixel will soften texture on any photograph. A target that allows 1.5 bits per pixel usually preserves faces and product edges. The guides show those numbers instead of hiding them behind a quality slider.

All tools on these pages process the selected file locally with the Canvas API. Nothing is uploaded, no account is created, and the downloaded file is generated in the browser tab. The homepage compressor handles batches and ZIP downloads; the guide tools are deliberately smaller so you can test one decision at a time.

Quick facts

  • 20KB = 20,480 bytes in most tools.
  • JPEG is lossy; every save loses detail.
  • Resizing changes pixels; quality changes bits per pixel.
  • Canvas export strips EXIF metadata.
